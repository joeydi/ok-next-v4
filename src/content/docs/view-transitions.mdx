`PageTransition.tsx` starts the transition and sets where the circle opens; the `.page` rules in `src/app/globals.css` animate it. Every timing and amount on this page is a `--view-transition-*` variable there, and every curve an `--ease-*` token, read from the CSS.

Times count from when the browser starts the view transition, once the new page has rendered. Each bar draws its easing curve: height is how far the animation has progressed.

## Two gradients from one radius

<DocFigure>
  <MaskDiagram />
</DocFigure>

The radius is `r = --reveal × 2.5 × reach ÷ --zoom`, where **reach** is the distance from the start point to the farthest corner of the screen. `--reveal` is a registered `<number>`, so it can animate from 0 to 1 and the gradient follows it.

**New page:** solid inside 0.4r, then an S-shaped fade to nothing at r. At `--reveal: 1` the solid centre is exactly reach across, so the page covers the screen as the animation ends.

**Old page:** hidden inside 0.4r, fully visible from 0.7r. It's gone wherever the new page is solid, so it never shows through gaps in the new page. In the shaded band, both pages are partly visible.

**The zoom is cancelled out.** Each mask is drawn in its own snapshot's coordinates, so it zooms with its page. The zoom runs through a registered `--zoom` that sets `scale`, and the radius is divided by it, so both circles always measure the same on screen.

## Where the circle opens

<DocCards>
  <DocCard label="Click" title="Pointer position">
    A capturing `click` listener records `clientX` and `clientY` when the target is inside a link.
  </DocCard>
  <DocCard label="Keyboard" title="Centre of the link">
    Enter on a link fires a click with `detail === 0` and no coordinates, so the centre of the link's box is used.
  </DocCard>
  <DocCard label="Back / forward" title="Centre of the screen">
    There's no click. `popstate` clears any stored point, so the reveal starts from the middle.
  </DocCard>
</DocCards>

Each snapshot is as large as its element (often far taller than the screen) and placed by its group's transform. Once the transition is ready, `onExit` and `onEnter` subtract each group's offset and write the point into that snapshot's own coordinates. Both pages render `main` and a footer, so there are four rules. These came from a click on the Digital production card:

```css
/* injected into <head>, removed when the transition ends */
::view-transition-old(_t_0_) { --reveal-x: 84px; --reveal-y: 1753px; --reveal-reach: 1481.6px; }
::view-transition-old(_t_0__1) { --reveal-x: 84px; --reveal-y: -499px; --reveal-reach: 1481.6px; }
::view-transition-new(_t_1_) { --reveal-x: 84px; --reveal-y: 215px; --reveal-reach: 1481.6px; }
::view-transition-new(_t_1__1) { --reveal-x: 84px; --reveal-y: -3642px; --reveal-reach: 1481.6px; }
```

The same point is the `transform-origin` for both pages, so the zoom also starts from it.

## Rows keep the old fade

Filtering the notes list animates rows, not pages. Rows that leave or arrive use their own `.filter` class with the fade the pages used before, and rows that stay slide to their new place. The footer is lifted out as `notes-footer` so it slides with them.
