# okaypl.us

Next.js 16 (App Router) + React 19 + Tailwind v4 + MDX, deployed on Vercel. Every route is statically generated. The README covers setup, the notes frontmatter and the media workflow in more detail.
The original design handoff lives in `design_handoff_okayplus_site/`. Treat it as the visual reference (1440px comps in `screenshots/`). Two service pages were renamed after the handoff: `02-creative-production` is now `/digital-production` and `04-tools-for-better-work` is now `/business-tools`.

- **Tokens** — colours (`--color-*`), easing (`--ease-*`), fonts and utilities (`px-page`, `grid-12`, `mono-label`, `mono-text`, `display`, `stripes`, `nudge`) and the shared hover treatment (`hover-card`, `hover-title`, `hover-lift`) are in `src/app/globals.css`. Use existing tokens rather than raw hex values or cubic-beziers.
- **Fluid scale** — `src/app/fluid.css` is generated by `node scripts/fluid.mjs`; edit the script, not the CSS. Tokens (`text-fl-*`, `*-fl-*` spacing, `px-page`) scale linearly 320→1920px and hit the exact design px at 1440. Use them instead of fixed px. It also generates Gelica's line-heights, one per size on two scales: `leading-heading-*` for headings and `leading-display-text-*` for running text (the note lead, list items, quotes). Its letter-spacing is a third per-size scale, `tracking-display-*`, for headings and running text alike. Give Gelica the ones matching its size, as in `text-fl-60 leading-heading-60 tracking-display-60`.
- **Page width** — wrap page-level blocks in `<Container>` (`src/components/Container.tsx`, takes `as`): gutter padding, capped at `--container-page` (1920px, set in `fluid.mjs`) and centred. Full-bleed backgrounds go on a parent. For sizes taken from the comp as a share of the viewport, use `calc(N*var(--pvw))`, not `Nvw`, so they stop growing at the cap too.
- **Copy** — Service page copy is data in `src/data/services.ts`, which also drives the homepage service cards (`*word*` in an H1 renders pink). `src/data/home.ts` holds the principles and testimonials; the home hero and about copy is inline in `src/app/page.tsx`, and the shared contact block is in `src/components/Footer.tsx`. Site constants (email, booking URL, nav) are in `src/data/site.ts`.
- **Service routes** — each service is a folder (`page.tsx` + `opengraph-image.tsx`) that renders `ServicePage` from `services[slug]`. Adding or renaming one also means updating `ServiceSlug` and `NAV` in `site.ts`; the sitemap and social cards follow `services`.
- **Illustrations** — `src/components/illustrations/`: WebGL2 scenes (`gl/scenes/*.ts`, each a `frame(t)` of boxes and balls, registered in `gl/scenes/index.ts`) drawn by a small renderer with soft shadows and analytic AO (`gl/renderer.ts`, `gl/shaders.ts`) inside `Stage`'s fixed 620×660 frame, which scales to its container. `GLIllustration` server-renders a poster of the scene's `posterTime` frame, starts WebGL when the page is idle and the illustration near the viewport, and stops off screen; under `prefers-reduced-motion` only the poster shows. A scene can also define `play()` + `hitArea` (the puzzle cube does): on the page a stateful player replaces `frame(t)` and takes drags inside that outline, while posters and the lab still use `frame(t)`. After changing a scene or `DEFAULT_SETTINGS`, the posters in `public/illustrations/` are stale: say so, since they're re-saved from the dev-only `/admin/illustrations` in a browser.
- **Media** — images/videos live in R2; `src/data/media.json` (committed, written by `scripts/media.mjs` and the dev-only `/admin/media`) describes them. Don't hand-edit it beyond alt/caption text. Its `og/` entries are saved social cards, written by `/admin/og`. Pass `getMedia(key)` from `src/lib/media.ts` (server-only: the manifest carries blur placeholders) to `Placeholder`/`Figure`; `MediaKey` is typed from the manifest, so unknown keys fail type-checking and the build. Client-safe URL helpers are in `src/lib/media-url.ts`. Media URLs need `NEXT_PUBLIC_MEDIA_HOST`.
- **Dev-only routes** — `*.dev.tsx` / `*.dev.ts` files exist only under `next dev` (`pageExtensions` in `next.config.ts`), so they never ship. Generated route types don't include them; type their props by hand.
- **Diagrams** — technique diagrams for notes: an exploded iso stack of plates, built per note in `src/components/diagrams/<note-slug>/` on the shared kit in `src/components/diagrams/` (`stack.tsx`, `parts.tsx`, `DiagramFigure`, `useLoop`, and `Jog`, the jog wheel every diagram gets) and imported locally in that note's MDX, not registered. Each has an entry in the dev-only `/admin/diagrams` lab (`registry.tsx`). Follow `.claude/skills/diagram/SKILL.md` to make or change one, and delete exploration variants once one is chosen.
- **Notes / case studies** — `src/content/notes/*.mdx`; the filename is the slug. Frontmatter is parsed + validated in `src/lib/notes.ts` (bad tags or media keys throw at build). `draft: true` shows in dev only. MDX components (`Lead`, `Figure`, `PullQuote`, `TocAnchor`, `Profile`) are registered in `src/mdx-components.tsx` and defined in `src/components/mdx.tsx`; article grid layout lives in the `.note-body` rules in `globals.css`.
- **Routes** — every public page is listed once, in `sitePaths()` (`src/lib/routes.ts`), which the sitemap, social cards, `/admin/og` and media usage read. A new kind of page goes there (services and notes are picked up on their own); `llms.txt` is hand-written and keeps its own list.
- **Social cards** — each route's card is described once in `src/lib/og-cards.ts` (`ogCard`), and its `opengraph-image.tsx` calls `ogImage(path)` from `src/lib/og.tsx`. That serves the Gelica card saved in the media store (`og/<name>-<hash>.png`, captured from the browser-drawn `OgCardHtml` by the dev-only `/admin/og`), or falls back to `renderOg` (Satori: Hanken Grotesk, since Adobe Fonts can't be used server-side; JPEG/PNG only) with a build warning when it's missing or stale. A card's title width, tuned by a slider in `/admin/og`, is kept in `src/data/og-title-widths.json` (written by that page's Save; the column sizes are in `src/lib/og-title.ts`). The hash covers the card's text, image, illustration, title width (when tuned) and `CARD_VERSION`: when a card's copy, image or layout changes, say it needs re-saving; when the layout (`renderOg`, `OgCardHtml`) or a poster it draws changes, bump `CARD_VERSION`.
- **Structured data** — JSON-LD builders and the `<JsonLd>` component are in `src/lib/jsonld.tsx` (typed with `schema-dts`). The layout emits the site graph (Person, ProfessionalService, WebSite); service pages (via `ServicePage`), notes and `/notes` add their own nodes, which point back at those by `@id`. A new kind of route should add its own builder there.
- **Page transitions** — `PageTransition` wraps pages in React's `<ViewTransition>`; the reveal animations are the `.page` rules in `globals.css`, timed by the `--view-transition-*` variables on `:root`. Each page renders its own `<main id="main">` and footer.
- **Design docs** — `src/content/docs/*.mdx`, shown in the dev-only admin at `/admin/docs/<slug>` and listed in its sidebar from their frontmatter (`src/lib/docs.ts`). They read every value from `globals.css` through `src/lib/tokens.ts`, and their visuals are `src/components/docs/` (passed to the MDX by the docs page, not registered for notes). `npm run check` fails on a literal colour or curve there. Follow `.claude/skills/design-doc/SKILL.md` to write one.

## Checks

- `npm run check` (Biome lint + format + import order) must pass. `npm run format` fixes formatting and import order. Biome's `useReactCompiler` rule is on, so components must follow the Rules of React (no mutating props/refs during render, etc.). There is no ESLint or Prettier script; Markdown, MDX and HTML are formatted by Prettier in the editor only.
- `npm run build` type-checks and validates notes and media keys. There is no test suite.
- **Verify visually** against the design screenshots at 1440 plus 320/390/768/1024/1920 before calling layout work done.

## Commits
