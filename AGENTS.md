# okaypl.us

Next.js 16 (App Router) + React 19 + Tailwind v4 + MDX, deployed on Vercel. Every route is statically generated. The README covers setup, the notes frontmatter and the media workflow in more detail.
The original design handoff lives in `design_handoff_okayplus_site/`. Treat it as the visual reference (1440px comps in `screenshots/`). Two service pages were renamed after the handoff: `02-creative-production` is now `/digital-production` and `04-tools-for-better-work` is now `/business-tools`.

- **Tokens** — colours (`--color-*`), easing (`--ease-*`), fonts and utilities (`px-page`, `grid-12`, `mono-label`, `display`, `stripes`, `nudge`) and the shared hover treatment (`hover-card`, `hover-title`, `hover-lift`) are in `src/app/globals.css`. Use existing tokens rather than raw hex values or cubic-beziers. `docs/*.html` copy token, easing and page-transition values by hand, so update them when those change.
- **Fluid scale** — `src/app/fluid.css` is generated by `node scripts/fluid.mjs`; edit the script, not the CSS. Tokens (`text-fl-*`, `*-fl-*` spacing, `px-page`) scale linearly 320→1920px and hit the exact design px at 1440. Use them instead of fixed px.
- **Page width** — wrap page-level blocks in `<Container>` (`src/components/Container.tsx`, takes `as`): gutter padding, capped at `--container-page` (1920px, set in `fluid.mjs`) and centred. Full-bleed backgrounds go on a parent. For sizes taken from the comp as a share of the viewport, use `calc(N*var(--pvw))`, not `Nvw`, so they stop growing at the cap too.
- **Copy** — Service page copy is data in `src/data/services.ts`, which also drives the homepage service cards (`*word*` in an H1 renders pink). `src/data/home.ts` holds the principles and testimonials; the home hero and about copy is inline in `src/app/page.tsx`, and the shared contact block is in `src/components/Footer.tsx`. Site constants (email, booking URL, nav) are in `src/data/site.ts`.
- **Service routes** — each service is a folder (`page.tsx` + `opengraph-image.tsx`) that renders `ServicePage` from `services[slug]`. Adding or renaming one also means updating `ServiceSlug`, `NAV` in `site.ts`, and the route list in `src/app/sitemap.ts`.
- **Illustrations** — `src/components/illustrations/`: WebGL2 scenes (`gl/scenes/*.ts`, each a `frame(t)` of boxes and balls, registered in `gl/scenes/index.ts`) drawn by a small renderer with soft shadows and analytic AO (`gl/renderer.ts`, `gl/shaders.ts`) inside `Stage`'s fixed 620×660 frame, which scales to its container. `GLIllustration` server-renders a poster of the scene's `posterTime` frame, starts WebGL when the page is idle and the illustration near the viewport, and stops off screen; under `prefers-reduced-motion` only the poster shows. A scene can also define `play()` + `hitArea` (the puzzle cube does): on the page a stateful player replaces `frame(t)` and takes drags inside that outline, while posters and the lab still use `frame(t)`. After changing a scene or `DEFAULT_SETTINGS`, the posters in `public/illustrations/` are stale: say so, since they're re-saved from the dev-only `/admin/illustrations` in a browser.
- **Media** — images/videos live in R2; `src/data/media.json` (committed, written by `scripts/media.mjs` and the dev-only `/admin/media`) describes them. Don't hand-edit it beyond alt/caption text. Pass `getMedia(key)` from `src/lib/media.ts` (server-only: the manifest carries blur placeholders) to `Placeholder`/`Figure`; `MediaKey` is typed from the manifest, so unknown keys fail type-checking and the build. Client-safe URL helpers are in `src/lib/media-url.ts`. Media URLs need `NEXT_PUBLIC_MEDIA_HOST`.
- **Dev-only routes** — `*.dev.tsx` / `*.dev.ts` files exist only under `next dev` (`pageExtensions` in `next.config.ts`), so they never ship. Generated route types don't include them; type their props by hand.
- **Notes / case studies** — `src/content/notes/*.mdx`; the filename is the slug. Frontmatter is parsed + validated in `src/lib/notes.ts` (bad tags or media keys throw at build). `draft: true` shows in dev only. MDX components (`Lead`, `Figure`, `PullQuote`, `TocAnchor`) are registered in `src/mdx-components.tsx` and defined in `src/components/mdx.tsx`; article grid layout lives in the `.note-body` rules in `globals.css`.
- **Social cards** — every route has an `opengraph-image.tsx` built on `renderOg` in `src/lib/og.tsx` (Satori: Hanken Grotesk, not Gelica, and JPEG/PNG only).
- **Page transitions** — `PageTransition` wraps pages in React's `<ViewTransition>`; the reveal animations are the `.page` rules in `globals.css`. Each page renders its own `<main id="main">` and footer.

## Checks

- `npm run check` (Biome lint + format + import order) must pass. `npm run format` fixes formatting and import order. Biome's `useReactCompiler` rule is on, so components must follow the Rules of React (no mutating props/refs during render, etc.). There is no ESLint or Prettier script; Markdown, MDX and HTML are formatted by Prettier in the editor only.
- `npm run build` type-checks and validates notes and media keys. There is no test suite.
- **Verify visually** against the design screenshots at 1440 plus 320/390/768/1024/1920 before calling layout work done.

## Commits

One sentence in the imperative, sentence case, no `feat:`-style prefix, describing what changed and why (see `git log`). Use American spelling in commit messages even where the code comments say "colour" or "centre".
